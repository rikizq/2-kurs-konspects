1. Анализ требований - определить предметную область, бизнес правила (что она будет делать? Как она будет делать? Для чего?), результат, четко сформулированное
2. Концептуальное проектирование - создает модель предметной области, которая отражает ее суть без привязки конкретной СУБД. Ключевые задачи этого этапа: Выделить сущности, определить атрибуты, выявить связи между сущностями, сформулировать ограничение целостности (ограничить возраст, ценник). Результат данного этапа будет ER диаграмма
![[Pasted image 20260917144822.png]]
3. Логическое проектирование - концептуальная модель преобразовывается в формулу, понятную конкретной СУБД. Ключевые задачи: перевод сущностей в таблицы, атрибуты - заголовки столбцов, подбираются типы данных, связи во внутренние и внешние ключи. Проводится нормализация (Процесс устранения избыточности и дублирования данных). Есть 4 формы нормализации: 1N, 2NF, 3NF и BCNF. Результатом данного этапа будет диаграмма с таблицами, типами данных и ключами.
![[Pasted image 20260917145756.png]]
4. Физическое проектирование - это самый технический этап на котором логическая модель адаптируется под конкретную СУБД. Ключевые задачи: Выбор СУБД с учетом требований проекта, проектирование сущностей, атрибутов первичных и внешних ключей, ввод тестовых данных, проектирование физических ограничений, реализация бизнес правил (процедуры, триггеры, запросы), постройка безопасности (определение прав доступа у пользователей). Результатом данного этапа будет готовая БД в конкретной СУБД, в которой можно носить реальные данные и использовать.
